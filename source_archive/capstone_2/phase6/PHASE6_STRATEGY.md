## 1. Contract and objective

- Phase 6 is **abstractive legal-document summarization**. Its primary score is **BERTScore F1**, not the macro F1 used in Phases 4 and 5. ROUGE-1 F1 and ROUGE-L F1 are secondary. The course's `evaluate_phase6.py` uses `bert_score.score(preds, refs, lang='en', batch_size=8)` without explicit IDF or baseline rescaling, and averages F1 across documents. It also checks exact ID equality and nonempty string summaries.
- Submit a ZIP containing only root-level `prediction.json`, preferably a list of `{"id":"original_test_id","summary":"..."}` records, exactly one per official test ID. Preserve original ID spelling and order in the manifest; prohibit duplicates, missing IDs, extra IDs, and blank summaries. Save six **different** output hashes.
- At least six substantially different experiments/submissions are required. Five must use different fine-tuning/adaptation techniques, including LORMA; one is generation-specific knowledge distillation. All four of the student's Phase 1 architectures must appear across the six. Changing only rank, learning rate, epochs, input length, or beam settings does not make a new technique. Each counted model starts from its original Phase 1 checkpoint and tokenizer. No other pretrained generator, external legal corpus, external LLM/API, or Phase 4/5 task-adapted checkpoint enters training or inference.
- The published evaluation script itself invokes an external pretrained **metric** model. Use that only for local evaluation if permitted by the course's evaluation materials; never use its representations, weights, or scores as a training target. Pin the evaluator and package versions, and verify how long candidate/reference summaries are handled before length tuning.

## 3. First-day data and metric audit: the architecture gate

1. Obtain only the official Phase 6 train/test files from a pinned dataset revision, or attach the released files. Record SHA-256, schema, IDs, count, source and summary token-length percentiles under all four original tokenizers, document/summary length ratio, and the rate at which references exceed the scorer's effective token limit. Inspect 30–50 actual document-summary pairs across short/median/very-long bins.
2. Group identical and near-duplicate documents before splitting. Make one deterministic group-held-out split: approximately 85% fit, 7.5% tuning, 7.5% untouched audit, adjusted if the dataset is unexpectedly small. Stratify by document length, reference length and source/court where available. Check cross-split text overlap. Do not use the untouched audit set for repeated decoder tuning.
3. Save an **oracle evidence ceiling**: for each training/tuning document, greedily select source sentences/paragraphs to maximize reference ROUGE under the 02 source budget. This uses the reference only to measure whether information can fit and to derive train-only selector labels. Never use reference-guided selections at validation/test inference.
4. Compare deterministic evidence inputs on a fixed sample: first 1024 tokens; beginning+end; section quotas; and a learned or lexical selector that covers facts, issue, reasoning and final holding. Record source coverage and oracle recall by document-length bin. A selector is promoted only if it improves generated-summary scores on held-out cases.
5. Run the official evaluator on known short examples and long examples. Record package versions, BERTScore hash/config, warnings/truncation, and whether locally calculated scores match its output. Use one scorer instance for repeated validation to avoid repeated model loading. BERTScore model use remains strictly evaluation-only.

## 4. Primary architecture: evidence selection followed by generation

**Base 02 encoder-decoder, initialized from its Phase 1 weights.** For each document, segment paragraphs/sentences while retaining original position. Select a source budget of at most 1024 original tokenizer tokens, reserving space for section separators. Use a stable mix of opening facts, issue/argument paragraphs, reasoning, and the final holding/order. Prefer a small train-only selector over pure heuristics only if it improves held-out BERTScore/ROUGE. A lightweight selector can learn from greedy reference-aligned paragraph labels, position, legal cue words and Phase 1 frozen encoder features; its inference never sees the reference. Keep the **same selection algorithm and budget** at generator train and inference time. Oracle-selected input is only an upper-bound diagnostic; if used for training augmentation, mix it with predicted selection so the generator does not learn an impossible inference distribution.

Teacher-force the reference summary into the pretrained causal decoder, with target-only cross-entropy and padding masked. Use the checkpoint's shared embedding/output projection and existing cross-attention. Begin with LoRA on encoder attention and decoder self/cross attention projections (including output projections), with a trained summary-control prefix token if necessary. This is the main high-score candidate because base 02 is already a real seq2seq architecture; it avoids randomly adding a full decoder to a classifier backbone.

For summaries that exceed base 02's 512-token decoder limit, decide from the audit whether to train two coherent target segments with a continuation cue or to cap at the scorer's effective range. For unusually long documents, test a **hierarchical fallback**: first select evidence from all sections, optionally generate short chunk notes with the *same Phase 1 based model*, then synthesize one final document summary. Train chunk targets only from train references aligned to chunks; evaluate the full two-stage pipeline on untouched documents. Use it only where it beats direct select-then-generate after extra generation cost. Never concatenate raw chunk summaries as the final output without testing coherence, redundancy and the abstractive requirement.

**Base 03 alternate.** Feed the same selected legal evidence as a bidirectional prefix, followed by a summary-start marker and causal summary tokens. Enforce `prefix length + generated length <= 1280` and verify the cached decoder matches non-cached logits. This model can be a strong independent candidate and the distillation student. **Bases 01/04** use a source prompt followed by summary tokens, with causal loss masked on source tokens. Base 04's local/global attention should be tested on long evidence; its larger nominal context alone is no guarantee that the final tokens can use every source detail.

Do not reuse Phase 4/5 classification heads or checkpoints. Their useful code is checkpoint loading, integrity checks, recovery, DDP, token caching, and archive construction.

## 6. Training and decoding without wasted compute

1. **Integrity/throughput pilot:** overfit 16–32 examples to verify targets, masks and generation; then benchmark 256–512 cases across short/long bins. Measure cases/hour, source/target tokens/sec, GPU memory, data-loader time, and generation/evaluator time. Estimate the full cost *before* starting each slot. Use dynamic padding, source/target length buckets, pretokenized caches and mixed precision. Enable activation checkpointing only where memory requires it. Compare one two-GPU DDP job with two independent one-GPU jobs; choose measured throughput, not assumed parallelism. Existing models have custom attention, so benchmark any PyTorch attention optimization and verify causal/prefix masks before adopting it.
2. **Budget by evidence, not a fixed long epoch count:** evaluate with deterministic decoding after about 0.5 and 1 epoch, then every approximately 0.5 epoch on a fixed representative tuning subset. Score the full tuning set at promising checkpoints. Use a lower pretrained-weight learning rate than new adapters/control embeddings, warmup, gradient clipping and a decaying schedule. Initial LoRA rank/adapter width can be modest; enlarge only after a short controlled pilot shows capacity limits. Save the best checkpoint by BERTScore F1, subject to ROUGE and factuality not collapsing. Stop only after a sustained plateau over several full validations, including at least one check after learning-rate decay; continue while the recent score trend is credibly positive. A hard cap is a resource safety limit, not an automatic final epoch. Keep 2–3 checkpoints for possible averaging only if validation helps.
3. **Decode grid:** choose reference-length bins from training only; on the tuning set compare compact beam sizes (for example 1, 3, 5), modest length penalties, and two output-length caps that fit each checkpoint. Record BERTScore precision, recall and F1, ROUGE, repetition and unsupported case names/statute numbers. Fix the decoder policy before the untouched audit pass. Never make a separate test-specific beam or length choice from private leaderboard noise. Use cached generation for all bases and batch by source length. For factuality, prefer grounded legal facts/holding and omit citations or numbers unsupported by the selected evidence.
4. **Early elimination:** all six methods must yield a genuine trained submission, but a weak method can stop after its predeclared learning/quality gate and still be reported honestly. Reallocate remaining GPU time to the best 01/02 model and its full-data refit. A reference-copy baseline, lead/end extractive baseline and oracle-evidence ceiling are diagnostics only; they do not count as abstractive submissions.
5. **Final refit:** after tuning and one untouched audit of the top one or two, refit the chosen model from its original Phase 1 checkpoint on all released training documents using the selected *number of optimizer steps*, evidence policy and decoding rule. Avoid blindly adding extra epochs. If the full refit cannot complete before the deadline, submit the best validated checkpoint rather than an unfinished run. Keep all six valid output files available early.

## 7. Decision/reporting rules

- Report mean BERTScore F1 with per-document distribution and short/medium/long bins; ROUGE-1/L; length ratio; distinct-n and repeated n-grams; coverage of facts, issue, reasoning and holding; unsupported names, dates, statute numbers and outcome reversals on a fixed manual sample. Since BERTScore measures similarity to a reference rather than source faithfulness, do not let a small gain justify unsupported legal claims.
- Use the untouched audit set **once** after the model and decoder policy are frozen. If it disagrees with tuning, investigate selection bias or document shift before refitting. Public/private leaderboard scores are separate from local estimates. No Phase 6 score can be promised until the released data and hidden references are evaluated.
- Store data revision/hash, tokenizer/checkpoint hashes, source and target budgets, selector version, split manifest, training curves, selected step, generation settings, validation predictions, metrics, cost and output hashes for each slot. Report whether the two adapter variants and distillation genuinely differ in code and training signal.
